# 本人と家族のコミュニケーションを戻す見直し

2026年9月17日（日本時間）。5つのAIレビュー担当が2つずつ、計10の立場で点検した整理。実際の市職員・専門家・利用者10名による評価ではない。

目的は「本人がおはようを押す → 家族が気づいてその場で返す → 本人が受け取り、ありがとうを返せる」。機能数より、この往復を迷わず行えることを優先する。

| 立場 | 問題・根本原因 | 今回の改善 |
| --- | --- | --- |
| 1 本人 | 家族の挨拶には返信対象IDがなく、自由メッセージ以外へ返せなかった | 挨拶・お願いへの返事も返信対象として保持する |
| 2 家族 | 本人の挨拶がホーム対象から除外され、返信ボタンが下段の閉じた欄にあった | 上部の「本人とのやりとり」に受信と返信を集める |
| 3 一人での利用 | 連携していない人に家族の操作を常時並べると煩雑になる | 確認済みの一人利用は予定・自分の用事を中心に保つ |
| 4 通信・復旧 | 通信確認中と相手がいない状態を同じ非表示処理にしていた | 会話の場所と保存済み表示を維持し、送信許可は最新の参加確認と分ける |
| 5 権限・安全 | 登録時roleが不変でも利用modeは変わるため、受信者の判定が誤っていた | 現在のmodeを優先。旧データだけroleを参照。承認・サーバー確認は引き続き必須 |
| 6 検査 | 以前のテストが「挨拶を表示しない」ことを正として固定していた | 生成された返信ボタンの処理を実行し、日本語本文と返信先を含む往復を検査 |
| 7 情報の並べ方 | 本人宛ての会話と家族同士の伝言が混在し、予定・用事より低い優先順位になった | 本人との会話を予定の前に置き、家族同士の伝言とは区別する |
| 8 長期保守 | 家庭切替後の古い購読・送信完了が新画面へ影響する余地がある | UID・家庭・世代を確認し、旧処理の表示変更と送信中状態の持越しを防ぐ |
| 9 地域での価値 | 日々の連絡が分かりにくいと、市への提案以前に継続利用が難しい | 本人発信と家族返信を中心に戻す。市の推薦や検証完了を新たに称さない |
| 10 継続負担 | 「返事はどこ？」への説明が運営者の負担になる | 連絡の直下に返す操作を置き、結果と再試行も同じ場所に表示する |

反対意見として「全部を出せば見つかる」は採用しない。一人利用は簡潔に、本人が参加したら会話、家族が参加したら家族間共有を表示する。通信待ちだけで利用場所を消さず、未承認・確認できない宛先へは送れない。

上部の常時「試験運用中」帯は依頼に沿って削除した。これを正式提供、実証完了、市の推薦、緊急対応の保証と解釈しない。利用開始時や使い方の情報を勝手に安全性確認済みへ書き換えない。Firebaseルール・課金・保存形式は今回変えない。

検査目標：挨拶の返信本文が空にならない／元の連絡に返る／本人がありがとうを返せる／通信待ちで送信不可／承認前は送信不可／失敗後再試行／入力中に新着が来ても返信先固定／家庭切替後に旧処理が新画面を書換えない。自動検査と、実際の別端末・Firebaseで行う通し確認は区別する。
