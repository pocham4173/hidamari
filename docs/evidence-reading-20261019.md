# 利用の集計を発表に使う前に

確認日：2026-10-19（日本時間）。コードの確認元：main `a1b556e0ed857242b4ccd7d894134896f5a8e9a6` の `worker.js`、`family-survey.js`。本番データとの照合は未実施。本書は集計表示を変更するものではない。

## 最初に分けること

「動くアプリがある」「開発者が試した」「第三者が使えた」「暮らしの負担が減った」は別の証拠。自分で複数の役を操作する試用は、機能の確認として残し、独立した複数人・複数家庭の利用実績には数えない。

開発者の試用で見つけた問題と直した内容は、実績として説明できる。利用者数を大きく見せる必要はない。第三者の効果が未測定でも、実装や検査まで未完成という意味にはならない。

## 現在の集計をどう読むか

| 表示 | コードが数えているもの | 発表での注意 |
| --- | --- | --- |
| 答えた家族：○人 | 有効な回答に含まれる uid の重複を除いた数。今月だけではなく取得した回答全体が対象 | 実人数の確認ではない。「回答アカウント数」と読み替える。同じ人が複数アカウントなら別々に数える |
| 今月の答え：○件 | 回答月が今月で、サーバーの回答時刻の月と一致する回答件数 | 回答件数と人数を区別する |
| 直近7日に操作があった世帯 | 集計対象の世帯のうち、7日間に本人側の操作が1件以上ある世帯 | 毎日使った割合ではない。分子／分母と対象期間を示す |
| 本人操作割合 | 本人参加世帯の28日間の本人側件数 ÷ 本人側と家族側の合計件数 | 自力で操作した人の割合ではない。家族のみの世帯はこの割合の対象外 |
| 3日目にも操作 | 集計上の開始日から3日目に本人側の操作がある世帯 | 3日連続の利用を意味しない |
| 8週目も続いている | 開始日から50〜56日目の7日間に対象の操作が1件以上ある世帯 | 8週間毎日使った意味ではない。対象なしを0%や100%に置き換えない |
| いちばん新しい1か月 | アカウントごとの最新の月次回答 | 全員が同じ月とは限らない。「今月の効果」と呼ばない |
| 同じ人どうしの差 | 同じ uid に使い始める前と月次の有効回答がある場合の差 | 現状は同じアカウント同士の比較。実人数や因果効果を保証しない |
| — | 比較に必要な回答・対象がそろっていない場合など | ゼロ、改善なし、不具合と決めつけない |

本人／家族の分類は集計時に取得した参加者情報に依存する。操作した実在の人物や年齢を、この集計だけで確定しない。削除済み家庭は除かれ、継続割合は高めに出る可能性がある。日次集計は順に処理されるため、前日までの完全な集計がそろったかは別途確認が必要。

アンケートの欠勤・早退の「2〜3回」を2、「4回以上」を4とする数値は選択肢の代表値であり、正確な回数の平均ではない。前後がそろっても、アプリだけが変化の原因とは言えない。

## 試験回答を消さずに整理する手順

1. 非公開の確認票で、開発者試用／協力者の試用／不明を区別する。アカウントと人の対応が不明なものは人数に換算しない。名前や回答内容を公開リポジトリへ載せない。
2. 試し用の世帯を丸ごと除外する既存設定 `USAGE_EXCLUDE_GROUPS` はあるが、実際の設定値は未確認。同一世帯に試験回答と実回答が混ざる場合、世帯の除外だけでは分離できない。
3. 先に除外対象と集計目的を確定し、除外前後の対象数・理由・欠測を残す。削除や本番設定変更を、この文書の作成と一緒に行わない。
4. 開発用の記録は検証の証拠として保存し、第三者の利用・負担軽減の集計とは別表にする。不明な回答を成功例として含めない。

### 次の表示修正の受け入れ条件（未実装）

- 「答えた家族○人」→「回答アカウント○件」。平均の分母は回答件数、前後比較は対応したアカウント数と正しく表記する。
- 「同じ人どうし」→「同じアカウントの前後」。見出しだけ直して他の「人」表示を残さない。
- 同一 uid の複数月、別 uid の試験回答、月次未回答、世帯除外、回答月不一致を架空データで検査する。
- 集計式を変えずに表現だけ直す場合も、数値が変わらないことを確認する。LINE側の変更は独立したPRと隔離テストまでとし、本番反映を行わない。

## 発表で使う説明のひな形

以下は実績の宣言ではなく、確認した範囲に合わせて使う原稿。第三者の数や効果を空想で埋めない。

> まいにこは、電話や訪問で確かめたことを家族で残し、次に連絡する人が見返せるアプリです。家族だけで使う場合、親のスマホ操作は必要ありません。開発段階では、記録・返事・予定を確認する一連の操作を試し、見つかった使いづらさを直しています。第三者による使いやすさや負担軽減は、これから確かめます。

### 審査で聞かれたとき

| 質問 | 証拠に沿った答え方 |
| --- | --- |
| 利用者は何人ですか | 開発者の試用、第三者の協力者、回答アカウントを分ける。未確認の実人数は答えない |
| ほかの家族チャットと何が違いますか | 誰がいつ電話・訪問したか、お願いへの返事を探せる流れを架空例で示す。探す速さの優位性は同条件の比較前には断定しない |
| 上田市と連携していますか | 公式の相談先やごみ収集情報への案内と、提携を区別する。正式な合意が未確認なら連携実績と呼ばない |
| 安全に動きますか | 対象SHAの検査、公開したファイル、実機確認を分ける。CI成功だけで本番の安全性を保証しない |
| ひと声の通知は使えますか | 既存実装と未マージの安全修正を区別する。PR成功を本番反映済みと説明しない |
