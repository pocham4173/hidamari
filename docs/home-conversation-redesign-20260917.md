# ホームで会話を完結させる改良

2026年9月17日。ユーザーから「説明が複雑」「本人からの返事がホームに出ない」と再指摘を受けたため、以下の10の枠組みで設計を見直した。外部の専門家10名が実際に評価したものではない。

## ゴール

本人が挨拶する → 家族がホームで読む → その下で返す → 本人がホームで読む → 本人の「ありがとう」が家族のホームの先頭に出る。この一往復で、設定や使い方を開く必要がないこと。

## 事実と判断（FACTVSOPINION）

コードで確認した事実：旧版は参加状況によって会話欄全体を非表示にする。当日の記録だけを購読する。返事を古い元メッセージの下に入れ、元メッセージの日時で並べる。本人の `family-message-back` には直接返事する操作がなかった。前回のテストは単体関数中心で、これらの表示仕様を正としていた。

未確認の事実：利用者本人の実際の参加情報、両端末が同じアカウントか、通信状態。実データを読み取って原因を断定したわけではない。

設計判断：ホームの会話の場所は固定する。表示と送信権限を分ける。新しい返事を単独の行として先頭へ出す。設定の説明を増やすことでは解決しない。

## WHY5

| なぜ | 確認した設計上の原因 |
| --- | --- |
| 返事が見つからない | 会話欄自体が消える、または古い挨拶の下に入る |
| 欄が消える | 参加人数・利用画面の判定を表示の条件にしていた |
| 新しい返事が下に入る | 会話を親子でまとめ、親の古い日時で並べていた |
| 翌日も見つからない | 当日の生活記録と会話の取得期間を同一にしていた |
| 修正後も指摘が続いた | 部分的な動作テストが中心で、「実際のホームの見える場所で往復できるか」を検査していなかった |

## PREMORTEM：失敗する三つの経路

1. 必要な連絡が見つからず、利用者が諦める。会話欄の常設・新着順・直下の返信操作で対処する。
2. 表示改善のつもりで未承認者にも送信・閲覧させる。Firestoreルールを維持し、確認済みの相手への送信条件を残す。
3. 修正のたびに説明と問い合わせが増え、企画者が支えきれなくなる。ホームの手順を固定し、実HTMLと別アカウントでの往復検査を公開前の必須検査にする。

## MENTOR：製品責任者としての判断

今回は新しい事業機能を増やさず、最も大切な会話の一往復へ集中する。著名人の発言や推薦を引用したものではない。「できる操作が多い」ではなく「使う人が次の操作を探さない」を判断基準にする。

## SECURITY

- サーバーの承認制、家庭の境界、書き込みの本人UID制限は変更しない。
- 通信・参加の確認ができないときは会話を読めても送信しない。保存成功を既読とは表示しない。
- 返信先IDを元の連絡に固定する。再送・新着・家庭切替で別の相手の内容へ置き換えない。
- 伝言は文字としてエスケープし、入力したHTMLが実行されないことを検査する。
- 当日だけの取得を、新しい順で最大100件の記録取得へ変更する。全履歴の無制限取得や有料サービス追加は行わない。それより前の会話は既存の履歴から確認する。
- 過去のお薬の声かけを今日の指示として表示しない。服薬記録は押した記録であり、実際の服用の証明ではない。

## TESTCASE

| 場面 | 合格条件 |
| --- | --- |
| 本人→家族→本人→家族 | 元の連絡IDを保って往復し、新しい返事がホームの最初に表示される |
| 返事へもう一度返す | 本人の「ありがとう」のすぐ下から続けて返せる |
| 日付が変わる | 前日の最近の連絡が日付付きでホームに残る |
| 一人・未確認・利用画面変更 | ホームの会話欄自体は消えず、未確認の送信を許可しない |
| 通信断・再読み込み | 内容と入力中の文章を保ち、送信を止め、復帰後に再開する |
| 承認待ち | 他の家族の会話を取得できず、送信できない |
| 新着・二重押し・別家庭への切替 | 返信先・送信済み状態・家庭の境界を守る |
| HTML入力・不正な返信の循環 | コードを実行せず、会話を再帰処理で隠したり停止したりしない |
| 会話が多い | 家族ホームでは3件、その前は開いて確認。開いた履歴は新着で勝手に閉じない |

検査は単体処理に加え、公開用HTMLの親要素・非表示・折りたたみまで含むDOM検査、Firestore Emulator上の独立した本人・家族アカウントでの受信・返信・通信断・未承認者拒否を実行する。iPhone実機の押し心地と利用者の実アカウント状態の確認とは区別する。

## SOP：普段の使い方

1. ホームを開く。いちばん新しい連絡を読む。
2. その連絡の下で返事を選ぶ。言葉で返すときは「言葉を書いて返す」を押す。
3. 「返事を送りました」を確認する。通信で止まったときは、その場の「もう一度読み込む」を押す。

## MILESTONE と指標

公開までの順序は、表示条件の再現 → ホーム再設計 → 別アカウントの自動往復・安全検査 → 本番公開ファイルの確認。実際の利用確認では、本人と家族の一往復が補足説明なしに完了したか、返事を探して設定へ移動した回数、送信失敗後に文章が失われた件数を記録する。今回の目標は、設定への寄り道0回・文章消失0件・返信先の取り違え0件。達成済みの実証結果や勝率としては扱わない。
