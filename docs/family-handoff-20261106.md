# 家族の連絡を次の人へ渡す：11月6日の追加依頼

目的は毎日の起動・返信を増やすことではなく、家族がしたことを次の家族に渡しやすくすること。確認の重複や引継ぎの負担が減るかは仮説で、実測していない。

## 今回の完成条件と実装

1. 家族だけで使うホームの既存「今日の様子」で、読み込んだ今日の電話・訪問のうち直近1件を、記録者と記録時刻付きで先に出す。食事などが続いても埋もれさせない。ほかの記録・メモは新しい順で2件まで。同じ記録を重複させず、計3件まで。
2. 家族の様子入力のメモを「次の人に残すひとこと（任意）」とし、既存の「次の用事」を入力する画面への入口を置く。入力欄に明示ラベルを追加。押すだけでは送信・担当指定・約束を保存しない。
3. 通信未確認の保存済み表示には「最新かは未確認」と表示。保存済み0件から今日の記録なしと断定しない。

親の操作なしで使う既存のモードから改善する。本人も参加するモードのホームへ新しい枠を増やすことは今回は見送る。本人画面の並び・日付・天気・音声・挨拶・服薬記録は変えない。

## 観察→原因→改善→確認

観察：renderTodayQuickRecordsはcare-logの最後3件だけを表示し、memoを除外。電話のあとに食事の記録が重なると電話が見えなくなる。架空データで追加テストが修正前に失敗した。

原因：新しいボタン記録だけを優先する表示で、連絡を引き継ぐための記録の種類を考慮していない。

改善：既存の同じ取得結果から電話・訪問を優先し、memoも表示候補に含める。追加の取得や保存項目は不要。記録時刻を実際に電話・訪問した時刻と誤認しないよう「記録」を付ける。

確認：修正後、電話が埋もれない・メモ表示・3件上限・重複なし・配列順に依存しない直近表示・保存済み表示と空状態の区別が成功。既存テストの関数抽出位置と時刻表記を更新。基本44/44、home-reliability、conversation-date、pilot-safety、household-ui成功。CI結果・SHAはPR本文に記録。

## 判断と限界

情報を1枠増やす案に対し、長いホームに戻る懸念があるため既存の枠・3件上限を採用した。家族への返信・確認を必須化する案、自動既読、自動担当・日時の約束は不採用。電話していない日を警告することもしない。

直近とは取得済み最大100件のうち今日の電話・訪問。全履歴で最後の連絡ではない。古い履歴はホームに追加しない。未記録なら実際の電話・訪問の有無は分からず、これを理由に必要な電話を省いてよいとは案内しない。手書きメモの内容をAIで予定や担当へ自動変換しない。

VMによる表示・日付切替等の隔離検査であり、実機の読みやすさ・家族の負担軽減は未確認。権限・認証・LINE・実利用者データを変更しない。今回の完成条件で区切り、マージ・公開はしない。
