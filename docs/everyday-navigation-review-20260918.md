# 毎日の操作を先にする画面整理

依頼：「説明が増えて使いにくい。本人に家族の参加確認を求めない。入口を整理し、安心のお薬手帳・電話を上へ」。5つのAI担当が2つずつ、計10の立場でコードと提供画像を確認した。実際の高齢者10名による利用試験ではない。

## 原因

日常の操作、導入作業、家庭の管理、使い方の説明を同じ強さで置いていた。本人の返信ができない状態に対し、参加管理へ誘導するボタンを追加したため、受信した連絡を読むだけの場面にも設定判断を求めていた。入口の「本人と家族が使う」は実際には家族用端末の選択で、名称と行き先が一致していなかった。

## 10視点の結論

| 立場 | 判断と対応 |
| --- | --- |
| 高齢の本人 | ホームに参加管理のボタンを出さない。今できる操作に絞る |
| 会話の継続性 | 届いた連絡・送信結果を残す。返信先がいないと確認できたときだけ返信の選択肢を隠す |
| 初めて使う人 | このスマホを誰が操作するかで「本人が使う」「家族が使う」を選ぶ |
| 視覚・操作のしやすさ | インストールを利用開始より下の補助操作へ。文字を小さく詰めず、説明と重複選択を減らす |
| 日常の介護者 | 安心の先頭をお薬手帳、その次を電話に。番号登録より保存済みの電話を先に見せる |
| 情報設計 | 相談・タグ・防災は下へ。お薬の共有メモと連絡先追加は折りたたむ |
| 安全・プライバシー | 返信の承認条件・通信確認・家庭の境界は変えない。写真と共有メモの保存範囲は残す |
| 通信不良 | 不明状態を「家族がいない」と扱わない。通信確認中は同じ場所で待機・再読み込みできる |
| 運営・サポート | ボタンの名称と行き先を合わせ、ヘルプの旧経路も修正。説明パネルの追加で解決しない |
| 回帰品質 | 公開HTMLと実処理で、非表示の親要素、電話リンク、家族モードの表示制御を確認 |

## 見つかった追加不具合

電話・連絡先に `family-only-card` が付いており、通常の家族モードでは非表示になっていた。既存の連絡先購読・権限はそのままに、不要な表示制限を外した。登録済みの電話一覧は、追加フォームの折りたたみの外に置く。

入口の「招待された方」は常に家族モードへ進む重複ボタンだった。本人・家族いずれも役割を選んだ後に招待コードで参加できる既存の流れへ統一し、誤った画面を選ばせない。

## 反対意見・例外への対応

- 返信欄を全部消すと「連絡が消えた」を再発する：届いた本文と送信結果は残し、使えない選択肢だけを隠す。
- 入力欄を折りたたむと登録できない：見出しから開けることを検査し、普段の電話操作は折りたたみ外に残す。
- 導入や復旧が見つからなくなる：入口の下に控えめな操作として残す。削除は利用終了の中に置き、確認手順を変えない。
- 情報を減らして誤認させる：保存先・共有範囲・処方確認など、判断に必要な注意は関連機能の中に残す。

## 目標と確認

入口の主役は役割選択。本人が受信した連絡を読むために設定へ移動しない。家族は「安心」を開くと、お薬手帳と登録済み電話が相談・タグより先に見つかることを目標にする。

新規の実DOMテストは、家族不在でも連絡と送信結果が残ること、通信復帰で同じ返信操作が戻ること、通常の家族モードで電話リンクが表示されることを確認する。既存の会話・音声・承認・データ削除の検査も維持する。操作回数や理解度の実利用改善率はまだ測定していない。

今後の追加判断も「普段の利用に必要か」「その場所で使えるか」「説明を読まずに行き先が分かるか」を基準にする。新しい課金サービスや権限の変更は行わない。
