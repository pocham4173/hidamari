# 記録を見つけやすいか：架空データによる比較手順
作成：2026-10-18。状態：手順・課題・採点表を準備済み。利用者による測定は未実施。
対象：家族だけで使うまいにこ。親のスマホ操作を必要としない利用方法に限定する。
関連：[改善台帳](shinshu-contest-review-20261017.md)、[既存の確認票](../PILOT_FEEDBACK.md)。

## この確認で分かること
家族が「最後に誰が電話・訪問したか」を正確に見つけられるかを確かめる。
記録数の多さ、健康改善、介護予防、実生活での4週継続は、この短い操作確認では証明できない。

## 実施前の条件
- 実データ、実アカウント、本番Firebase、実LINE通知を使用しない。参加者への依頼・募集はこの資料の追加だけでは開始しない。
- アプリの操作確認は専用の隔離環境が用意できた場合だけ実施。家庭Aと家庭Bを用意し、家庭Aの承認家族2名のみで共有を確認する。家庭Bの情報が見える場合は中止。
- 下の過去日時を本番の記録ボタンで再現しない。記録ボタンには過去日時の指定がない。隔離環境の準備担当が架空の初期データを用意し、画面に表示された日時・登録者を正答表と照合してから開始する。
- 隔離環境を用意できなければ「未実施」。静止画や紙で確認した結果は「静止画の読み取り」と明記し、アプリの操作時間には混ぜない。
- 現在はPR #193のメモ重複防止が下書きのまま。通信切断を含む保存の検証はその差分・検査記録を確認して別に行う。この比較で障害時の安全性まで合格としない。

すべて架空。体調・病歴・住所・個人名を含めない。AとBの優劣を競うものではない。
紙や家族チャット相当の比較用画面にも同じ6件を掲載し、情報の省略、関係のない会話の追加はしない。実際の家族LINEへ投稿しない。

## 課題と正答（準備担当用）
参加者へは質問だけ見せ、正答表は先に見せない。メモの予定を、実施済みの記録と取り違えないかも確認する。

| 質問 | セットA正答 | セットB正答 |
| --- | --- | --- |
| 最後に電話したのは、誰・何時？ | 家族B・14:20 | 家族B・17:20 |
| 最後に訪問したのは、誰・何時？ | 家族A・16:10 | 家族A・15:30 |
| 週末の訪問／電話は、実施済みと分かる？ | 分からない（訪問は相談中） | 分からない（電話は相談中） |

表示する日付は画面側とそろえる。日付の間違い、未表示、準備担当の取り違えがあれば、その試行は環境不備とし比較しない。

## 公平に比べる順番
2名以上で可能なら次の4通りを順に割り当てる。人数が足りなければ不足を報告し、学習による偏りが残ると記す。
1. まいにこA → 比較用B
2. 比較用A → まいにこB
3. まいにこB → 比較用A
4. 比較用B → まいにこA

開始する画面、文字サイズ、端末、履歴の6件、練習回数をそろえる。使い慣れの程度を任意で確認する。
どちらか片方だけ検索済み・答えを強調済みの状態にしない。検索やスクロールは、その方法が通常持つ操作を許可する。

## 測り方
- 質問を読み終え「始めてください」と伝えた時点から、本人が答えを確定した時点までを測る。
- 正しい／間違い／答えられない／途中中止／環境不備を分ける。提案する上限は各問120秒。実施前に上限を決め、途中で都合よく変えない。
- 手助けの有無、押し間違い、迷った箇所を短く残す。本人の病気や家庭事情は聞かない。
- 保存時間は別測定。「様子を記録する」を開く直前から保存完了表示まで。初回設定・招待承認と混ぜない。別の承認家族が見えるまでの時間も別欄。
- 日々の入力が「1分」と言えるかは未測定。自動テストの実行時間やAIの読み取り時間を利用者の操作時間として報告しない。

集計は実施数、正答数、未回答・中止・環境不備数、手助けありの数を先に示す。成功分の時間だけで速さを誇張しない。
少人数は各結果と条件を見て改善箇所を探す段階。効果の一般化や有意差、介護負担軽減の証明はしない。
4週継続は別途、開始時に定義した任意の追跡確認を行う。10月25日までに4週継続を完了扱いしない。
