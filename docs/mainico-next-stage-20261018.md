# まいにこ：80代の本人・家族の体験と、競争力を磨く設計案

確認日：2026年10月18日（日本時間）。確認したmain：`b90e9513dd8d6771176997183742a906f88b8d4d`。

これは開発判断のための提案であり、新機能の実装報告・効果実証・審査員による採点ではない。[改善台帳](shinshu-contest-review-20261017.md)、[3家庭確認票](../PILOT_FEEDBACK.md)、[企業向け検討](../EMPLOYER_VALUE_REVIEW.md)を補う。利用者数、継続率、支払意思、正式提携の実績は今回取得していない。

## 1. 提案の中心

**親のいつもの暮らしを変えず、家族が支えを引き継げる。**

最初に絞る利用場面は、「離れて暮らす80代の親に、複数の家族が電話・訪問している。誰が何を確認し、次に誰が動くかを毎回聞き直している家庭」。介護サービス利用前から始められ、必要になったときの相談にも記録を持っていける体験を目指す。これは顧客仮説であり、需要確認済みとはしない。

本人が操作したい場合は、予定を知る、家族に返事をする、お願いを伝えることを大切にする。操作を望まない場合は家族の記録から始める。80代を一律に「使えない人」と扱わず、本人の希望・見え方・押しやすさ・慣れに応じて確かめる。[S8]

家族だけで使うことと、本人に知らせず記録・共有することは同じではない。本人への説明、見せる相手、相談へ持ち出す内容を分かりやすくする。本人の未入力を異常・不在・安否の証拠として扱わない。

競争上の狙いは、**電話・訪問 → 短い記録 → 家族の引受け → 必要な相談**の一連の手順を、少ない説明で進められること。現段階では優位性の仮説である。比較で差が出なければ、機能を足す前に対象家庭・手順・提供方法を見直す。

画面の模倣は容易。長く選ばれる理由として育てるべきなのは、本人と家族による確認を重ねた手順、迷ったときの支援、復旧の信頼性、地域情報の更新体制。家族の記録を販売したり、囲い込んだりすることを競争力にしない。

## 5. 優先する改善は3つ

### ① 本人の「今日」を迷わず見られる画面

既存の本人画面を、同じ位置にある「今日の予定」「家族からの連絡」「ひとこと伝える」の3か所を中心に整理する設計案。予定や服薬等の必要な機能を削除するのではなく、利用者が必要なものを選べるようにする。

- 例：明日の家族の訪問を大きく示し、希望したときに読み上げる。「ひとこと伝える」から既存の挨拶・返事・お願いへ進む。
- 保存ができたことと家族が読んだことを混同しない。押し間違いの取り消しを見つけやすくする。
- 家族だけの利用と本人参加を切り替えても同じ家庭の記録を保つことを目標にする。本人確認・権限・既存データの継続は検証が必要で、自動移行を今回実装しない。
- 検証：80代の協力者が、予定を見る、返事をする、間違いを戻す課題を架空情報で試す。成功・迷い・助言回数・中止・本人の感想を残す。家族の感想で本人の評価を代用しない。

### ② 家族が「次にすること」を引き継げる画面

既存の記録・予定・やること・引受けを、「最後の電話／訪問」「次の予定」「助けが必要なこと」として同じ画面で整理する。引受け機能を新機能として数えない。

- 架空例：家族Aが電話を記録 → 家族Bが買い物を引き受ける → 次に開いた家族が経緯と未完了事項を確認する。
- 現在の「相談済みの担当メモ」と、実際に押された「私が引き受ける」を区別する。予定・引受け・完了も別の状態として読めるようにする。
- 貢献ランキングや入力の催促で家族を競わせない。変更や引受け取消しも迷わず確認できることを重視する。
- 検証：[架空データ比較手順](record-finding-trial-20261018.md)を土台に、普段の家族チャット／紙と同じ質問を解く。LINEのノート等を普段使う家庭ではその方法も比較対象に含める。練習量と順序をそろえ、時間だけでなく正答・失敗・二重入力の負担を見る。

### ③ 必要な記録だけを相談へ持っていける「相談の1枚」

既存の期間指定・印刷を土台に、「いつから」「実際にあったこと」「相談したいこと」を整理して選ぶ体験を設計する。印刷機能そのものを新規・独自と呼ばない。

- 記録した人・日時と原文を確かめ、観察した事実と家族の心配を分ける。本人・家族が見せる範囲を選んで確認する。AIによる診断、記録の自動送信、専門家への常時共有は追加しない。
- 上田の既存窓口へ持参・相談する流れを示す。掲載元・確認日・更新担当を残す。「情報掲載」「相談資料への意見」「実証協力」「正式提携」を分ける。
- 検証：架空例の1枚から、相談したい内容を第三者が読み取れるか確認する。専門家の意見は許可された協力が得られた後に記録し、未実施を合意済みにしない。

## 6. 継続運営も同じ提案に含める

最初の利用者は親と家族。支払者候補は家族本人、または働く家族を支える企業で、企業負担は既存資料にある検証対象の仮説。企業向けにはアプリ利用だけでなく、家族が始める説明・困ったときの窓口・地域情報の整備を含めた提供範囲を検討する。24時間対応や医療相談を約束しない。

支払意思は「便利そう」という感想と分け、誰の予算で、どの提供範囲に、どの条件なら支払うかを確認する。価格はその確認前に確定しない。費用は通信だけでなく、登録支援・問い合わせ・復旧対応・地域情報更新の時間を含める。企業へ家族の記録を渡すことを対価にしない。

上田で相談資料・案内・支援手順を確かめ、ほかの地域では相談先情報を差し替えられる構成を目指す。地域固有の内容と共通部分を分けることで広げ方を説明する。実際の提携先・導入地域が増えたという主張ではない。
