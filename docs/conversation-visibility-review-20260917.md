# 会話の見つけやすさを見直す10視点会議

2026年9月17日。5つのAIレビュー担当が2役ずつ、10の立場で検討した記録です。実在する専門家・市職員・利用者10名の会議や評価ではありません。

目標は、本人の「おはよう」に家族が返し、本人がその言葉を受け取れることです。予定・用事の管理に埋もれず、返事の場所と相手が分かる画面へ戻します。市の正式な推奨、実証完了、運営委託の決定を示すものではありません。

## 根本原因と採用案

| 視点 | 問題・反対意見 | 採用する改善 |
| --- | --- | --- |
| 1 本人 | 届いた言葉・保存結果・返信・過去の伝言が離れ、どれに返すのか分かりにくい。 | 「家族とのやりとり」に受信・返事・過去の連絡をまとめ、保存結果とは分ける。 |
| 2 家族 | 挨拶を最新1件に絞ると、以前の挨拶と返事の入口が消えたように見える。 | 今日の挨拶はそれぞれ表示し、各挨拶の直下から返せるようにする。 |
| 3 一人での利用 | 毎回「家族がいない」と説明されても、日々の用事には役立たない。 | 一人利用は予定・記録・自分のやることを中心にする。連携状況は設定で確認する。 |
| 4 通信・履歴 | 相手が現在つながっているかと、保存済みの会話を表示できるかを同じ条件にすると、会話を見失う。 | 履歴の表示と送信許可を分ける。通信確認中や参加未確認では送信を許可しない。 |
| 5 操作性 | 返信後にすべての操作がなくなると、会話を続けられないと思われる。 | 家族側に「続けて言葉を送る」を残す。本人の約0.65秒の押下感は維持する。 |
| 6 権限・誤送信 | 見せる範囲を広げるために承認確認や返信先の固定を外してはいけない。 | 既存の参加確認・返信対象・家庭切替時の確認を保つ。見えていることと、送れることを区別する。 |
| 7 地域への導入 | 市への提案文を増やしても、実際の一往復で迷えば価値は伝わらない。 | 本人発信→家族の返事→本人の受信を短い手順で示す。推薦済みなどの表現は加えない。 |
| 8 運営・問い合わせ | 「返事はどこ？」への個別説明が続くと、運営する人の負担が増える。 | 返す操作と結果を元の連絡の近くに置く。家族から先に送った言葉もホームで確認できるようにする。 |
| 9 検査 | ボタンの有無だけでは、別の挨拶へ返す間違いや通信待ちの誤操作を見逃す。 | 複数の挨拶、返信後の追加文、先送りしたメッセージ、通信未確認、家庭切替を回帰検査に含める。 |
| 10 長期保守 | 全期間の全文をホームへ並べると、記録が増えるほど日常操作が遠くなる。 | ホームは今日の会話を扱い、過去は履歴へつなぐ。日付をまたぐ返信などの未解決点を別に記録する。 |

全部の機能・説明・警告をホームに戻す案は採用しません。会話の場所を安定させ、詳しい説明は使い方へ置きます。返信速度や毎日の継続を評価する仕組みも今回の目的に含めません。

## 上部の試験帯について

今回の点検時、ローカルと公開HTMLの両方で、常設の「試験運用中｜実名・住所・電話・病歴…」帯は既に除去されていました。公開側にも本人と家族の返信コードが存在しました。

古い画面が開いたままなどの可能性はありますが、利用者の端末を確認せずにキャッシュを原因と断定しません。再読み込みを案内する場合も、登録や端末保存のお薬手帳を失うおそれがあるブラウザー保存データの消去は勧めません。帯がないことは正式運用・安全性の検証完了を意味しません。

## 確認する指標

以下は未測定の確認項目・目標で、達成実績や市全体への効果ではありません。

| 指標 | 測り方・目標 |
| --- | --- |
| 初回の一往復 | 試用を始めた家庭のうち、本人の挨拶→家族の返事→本人の受信確認まで進めた家庭数を記録する。途中でやめた家庭も分母に含め、まず参加した全家庭で成立を目指す。 |
| 返事の見つけやすさ | 家族が返事の場所を自力で見つけたか、説明や誘導が必要だったかを記録する。説明が必要だった場所を次の修正対象にする。 |
| 返信先の確実性 | 複数の挨拶・新着・家庭切替の検査で、意図しない連絡への返信0件を公開前の条件にする。 |
| 続ける会話 | 返事のあとに追加の言葉を送れたかを確認する。会話数や返信速度を利用者の評価には使わない。 |
| 問い合わせ負担 | 会話の場所に関する質問の件数と説明にかかった時間を記録する。改良前の比較記録がないため、削減したとは主張しない。 |

## 残る確認と別課題

- 実際の別端末・Firebaseで、招待・承認後の挨拶、返事、本人の受信、追加の言葉まで通して確認する。自動検査と実機確認は別に扱う。
- 一人利用、参加前、参加解除後、通信が切れたときに、履歴と送信ボタンの状態が矛盾しないことを確認する。
- 日付をまたいだ家族側の返信は、元の連絡の日付と対象の再確認を含む別課題として扱う。今回の今日の会話改善だけで解決済みとしない。
- 「お願い」への返信については、通信状態・二重送信・返信先確認をそろえる追加点検を別課題として残す。
- 利用者が説明なしに使えること、市が推奨できること、保守・問い合わせを継続できることは別の評価である。今回の画面改良を、そのまま市の推奨判断や運営体制の完成と扱わない。
